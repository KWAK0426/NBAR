# 관측자료와 상태 수정 안내

대상 파일: `site/data/nbar-data.js`

이 파일은 JSON 파일이 아니라 브라우저가 실행하는 JavaScript입니다. 문자열 따옴표, 쉼표, 중괄호를 유지합니다. 외부 라이브러리·데이터베이스·관리 화면은 필요하지 않습니다.

## 2. 최신 업데이트 시각

```js
window.NBAR_LAST_UPDATED = "2026.09.20 15:51";
```

메인과 현장관측 헤더가 같은 값을 읽습니다. 자료·상태를 실제로 수정했을 때 `YYYY.MM.DD HH:mm` 형태의 한국시간을 수동 입력합니다. 브라우저를 열거나 새로고침한 시간으로 자동 대체하지 않습니다.

## 3. 관측 항목의 필드

| 필드 | 자료형·예시 | 사용처 |
|---|---|---|
| `date` | 문자열 `2026.07.31` | 날짜 표시, 날짜별 진행 설정 키 |
| `coverType` | 농지 / 밭 / 나지 / 경사지 | 유형 탭과 집계 |
| `crop` | 벼 / 양배추 / 빈 문자열 | 작물 정보 |
| `site` | 문자열 | 대상지 표시와 관측 횟수 집계 |
| `purpose` | 짧은 문자열 | 관측 시기와 목록 |
| `purposeDetail` | 상세 문자열 | 추가 설명용 보유 필드; 현재 모든 화면에서 사용되지는 않음 |
| `cycle` | 문자열 `5회` | 회차 칸 수 계산 |
| `observationTime` | 문자열 `09:55~14:42` | 전체 관측 시간 |
| `imageCount` | 숫자 `5834` | 영상 개수. 쉼표·장 단위를 값에 넣지 않음 |
| `title` | 문자열 `[논 벼] - 김해 농지` | 관측 목록 제목 |
| `agency` | 문자열 | 촬영 기관. 현장관측 상세 "참여 기관" 칸에 표시. 2026-10-29 사용자 확인: 현재 목록은 모두 부산대 촬영 |
| `html` | `reports/파일명.html` | 개별 보고서 상대 경로 |
| `status` | `전처리 진행 중` 등 | 관측 전체 상태 표시 |
| `statusClass` | `progress`, `done`, `planned` 등 | 상태 배지의 CSS 클래스 |
| `processing` | 단계명·상태의 2열 배열 | 업무 5단계 표 |
| `schedule` | 항목명·값·설명의 3열 배열 | 타프 적용 여부, 상세정보 fallback |
| `mosaic` | 선택 문자열 또는 `{src, alt}` 객체 | RGB 모자이크. 현재 원본 데이터에는 없음 |

같은 날짜에 다른 대상지에서 찍은 관측이 있을 수 있습니다. 관측은 날짜+대상지(`site`)로 구분하고, `byDate` 설정 키도 `"2026.06.10 농업위성센터"`처럼 날짜 뒤에 대상지를 붙입니다. 날짜만 쓴 키는 그 날짜 관측이 하나일 때만 허용되며, `tools/check_data.cjs`가 검사합니다.

날짜, 사이클, 시간, 영상 수는 `schedule`에도 들어 있습니다. 현재 구조에서는 상위 값과 `schedule`을 함께 맞춰 수정합니다.

목록 제목은 작물이 있으면 `[논 벼]`, `[양배추]`를 사용합니다. 빈 작물에 대해서는 `[농지]`, `[나지]`, `[경사지]`처럼 씁니다. 피복 유형 탭의 농지·밭 구분은 그대로 둡니다.

## 4. 업무 5단계 수정

각 관측의 `processing`은 다음 순서를 유지합니다.

```js
processing: [
    ["자료 정리", "완료"],
    ["영상 처리", "진행 중"],
    ["품질 검토", "예정"],
    ["BRDF 분석", "예정"],
    ["보고서 작성", "예정"]
]
```

업무 상태는 `완료`, `진행 중`, `예정`을 사용합니다. ELC 세부의 `대상 아님`은 타프 여부로 자동 표시됩니다.

현재 기준은 자료 정리 전부 완료, 영상 처리 전부 진행 중, 품질 검토·BRDF 분석 전부 예정입니다. 보고서 작성은 6월 10일만 진행 중이고 나머지는 예정입니다.

`status`와 `statusClass`는 이 표로부터 자동 계산되지 않습니다. 전체 표시를 바꿀 경우 별도로 확인합니다. 자료 정리의 네 세부항목도 개별 저장값이 아니라 상위 자료 정리 상태에서 파생됩니다.

## 5. 영상 처리·품질 검토의 회차 완료 수

설정 객체:

- 영상 처리: `window.NBAR_MOSAIC_CYCLE_PROGRESS`
- 품질 검토: `window.NBAR_QUALITY_CYCLE_PROGRESS`

예시입니다. 실제 완료가 확인된 경우에만 숫자를 적용합니다.

```js
window.NBAR_MOSAIC_CYCLE_PROGRESS = {
    default: {
        panelCompletedCycles: 0,
        elcCompletedCycles: 0
    },
    byDate: {
        "2026.06.10 농업위성센터": {
            panelCompletedCycles: 2,
            elcCompletedCycles: 1
        }
    }
};
```

이 경우 6월 10일의 패널은 1·2회 완료, ELC는 1회 완료로 표시합니다. 이후 회차는 예정입니다. 품질 검토는 같은 모양을 `NBAR_QUALITY_CYCLE_PROGRESS`에서 따로 수정합니다.

- 완료 개수는 0~전체 사이클 사이 정수로 기록합니다.
- 현재 코드가 범위를 보정하더라도 입력값 자체를 정확히 적습니다.
- 타프 없는 날에는 ELC 완료 수를 적어도 화면은 대상 아님입니다.
- 다른 순서로 완료된 회차는 이 개수 모델로 표현할 수 없습니다.
- 상위 `processing` 표와는 자동 연동되지 않습니다. 실적 업데이트 때 양쪽을 확인합니다.
- 현재 배포 기준 파일의 `byDate`는 비어 있고 기본 완료 수는 모두 0입니다. 예시 숫자가 실제 실적은 아닙니다.

## 6. 타프 구성

기본 설치 구성:

```js
window.NBAR_TARP_DETAILS = {
    defaultInstalled: "PNU 3% / 36% / 56%",
    byDate: {
        "2026.06.10 농업위성센터": "PNU 3% / 36% / 56%, NIAS 2.5% / 20% / 30% / 50%"
    }
};
```

설치일은 2026.06.10, 06.12, 07.16, 07.31입니다. 나머지 4개 관측일은 미설치입니다.

설치 여부를 바꾸려면 해당 관측의 `schedule` 줄도 변경합니다.

```js
// 미설치
["반사도 타프", "미설치", "해당 관측일은 반사도 타프 미설치"]

// 설치 예시
["반사도 타프", "3%, 36%, 56%", "PNU 3종 반사도 타프 설치"]
```

현재 판정은 `schedule`의 값이 `미설치`인가에 달려 있습니다. 세부 구성은 `NBAR_TARP_DETAILS`에서 읽습니다. 두 위치를 함께 관리해야 합니다.

표시용 퍼센트와 실제 ELC 계산용 밴드별 반사도 계수는 별개입니다. 이 웹 데이터 문자열을 방사보정 프로그램의 계산 입력으로 바로 사용하지 않습니다.

## 7. 보고서 추가와 공개

2026-10-29부터 관측마다 보고서 폴더가 있습니다(`site/reports/<날짜_대상지>/`). 자세한 업로드 절차와 폴더 목록은 `docs/REPORT_UPLOAD_GUIDE.md`를 따릅니다.

1. 보고서를 해당 관측 폴더에 `index.html`로 넣습니다. 이미지·CSS·JS도 같은 폴더에 상대경로로 둡니다.
2. 관측의 `html` 값은 이미 `reports/<폴더>/index.html`로 되어 있어 고치지 않습니다.
3. 페이지가 열릴 때 파일이 있는지 확인(HEAD 요청)해서 버튼을 `HTML / 열기`로 바꿉니다. 파일이 없으면 `HTML / 준비 중`입니다.
4. `processing`의 `보고서 작성` 상태는 버튼과 별개입니다. 실제 상황에 맞게 따로 고칩니다(완료인데 파일이 없으면 `tools/check_data.cjs`가 오류로 표시).

6월 10일은 이미 공개된 주소를 유지합니다.

```js
html: "reports/2026-06-10_field_result_report.html"
```

파일 존재 확인은 웹 서버에서만 됩니다. 파일을 브라우저로 직접 열면(`file://`) 버튼이 모두 `준비 중`으로 보입니다.

과거 안내에 있던 `report_0630_joint_campaign.html`을 현재 연결로 되돌리지 않습니다. 분리 전 합본은 `2026-06-10_joint_field_elc_mosaic_report.html`로 별도 보존되어 있습니다.

## 8. RGB 모자이크 연결

예를 들어 이미지를 `site/assets/mosaics/2026-06-10_rgb.png`에 두고 해당 관측에 필드를 추가합니다.

```js
mosaic: {
    src: "assets/mosaics/2026-06-10_rgb.png",
    alt: "2026년 6월 10일 농업위성센터 RGB 모자이크"
},
```

현재 코드가 지원하는 간단한 표기도 있습니다.

```js
mosaic: "assets/mosaics/2026-06-10_rgb.png",
```

모든 경로는 `site/field_observation.html` 기준 상대경로입니다. `C:/...`, `F:/...` 등 개인 PC 경로를 넣으면 다른 사람이 볼 수 없습니다.

웹 미리보기에는 PNG/JPEG를 사용하고, 실제 반사도·DEM 분석자료는 원래 값과 지리정보를 보존하는 GeoTIFF 등으로 별도 관리합니다. 이번 패키지에는 UAV 원영상이나 DEM 원본은 없습니다.

## 9. 공용 프로토콜과 외부 문서

공용 프로토콜은 헤더 업데이트 표시 왼쪽의 버튼으로 연결하자는 요청이 있었습니다. 현재는 실제 DOCX와 버튼이 없습니다.

나중에 `site/docs/field_observation_protocol.docx`를 넣고 그 경로를 연결할 수 있습니다. 브라우저·운영체제에 따라 DOCX는 내려받기 또는 Word 연결로 동작하므로, 모든 브라우저에서 Word가 자동 실행된다고 보장하지 않습니다. 브라우저 미리보기가 필요하면 별도 PDF를 함께 제공하는 방식을 검토합니다.

## 10. 수정 후 확인

1. `site/index.html`과 현장관측 페이지에 데이터가 나오는지 확인합니다.
2. 농지 5·밭 1·나지 1·경사지 1개의 관측 목록을 확인합니다.
3. 7월 31일의 5회·09:55~14:42·5,834를 확인합니다.
4. 6월 10일의 NIAS 2.5/20/30/50% 표시를 확인합니다.
5. 미설치일의 영상 처리·품질 검토 ELC가 대상 아님인지 확인합니다.
6. 보고서 링크와 모자이크 이미지를 실제로 엽니다.
7. `NBAR_LAST_UPDATED`가 실제 수정 내용에 맞는지 확인합니다.

JavaScript 파일에 구문 오류가 있으면 관측 목록 전체가 비어 보일 수 있습니다. 브라우저 개발자도구의 Console도 함께 확인합니다.
