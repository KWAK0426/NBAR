## 소스와 공개 위치

`site/` 안의 HTML·데이터·이미지가 실행 소스다. 루트 `index.html`은 `./site/`로 연결한다.
Pages는 `main` 브랜치의 루트(`/`)를 공개하도록 설정되어 있다. 이후 push 시 다시 배포된다.
다음 수정도 `site/` 한 곳에서 한다. 루트에 같은 사이트 파일을 다시 복제하지 않는다.
기존 `report_0630_joint_campaign.html` 주소와 `01_htmls/`는 그대로 보존한다.

관측 데이터의 표시 갱신일은 **2026.09.20 15:51**이다. 이번 배포일과 다르다.
자료는 패키지의 8개 관측·38사이클 기준이며, 다른 드론 관리 현황판의 최신 실적을 합치지 않았다.

## 남아 있는 문제

- 보고서 7개는 미작성이고 비활성 상태다. [기존 목록](WEBSITE_HANDOFF.md#8-미등록-파일과-후속-작업)을 참고한다.
- 6/10 결과 보고서와 보존 합본에 같은 PNG 3종이 손상되어 있다(문서 2개에 총 6개).
  `Case 04 Tarp-wise Error`, `Case 08 Tarp-wise error`, `Case 09 band-wise error`이다.
  원본 출력 그림을 확보하기 전 과학적 결과를 임의로 재작성하지 않는다.
- MathJax는 외부 CDN을 사용한다. 오프라인 수식 렌더링을 보장하지 않는다.
- 처리 완료 회차는 순서형 개수 모델이다. 임의의 완료 회차 집합을 표시하지 못한다.
- 이 사이트의 수식 설명이 실제 처리 코드까지 검증되었다는 뜻은 아니다.

## 다음 작업 방법

작업 전 pull → 위 기록 확인 → 요청 범위 수정 → 링크·데이터·관련 화면 확인 →
새 업데이트 파일 작성 → 현재 상태 갱신 → commit/push → 실제 주소 확인 순서로 진행한다.
기존 변경이 있거나 원격이 앞서 있으면 먼저 비교한다. 타인의 변경을 지우지 않는다.

## 교수님 GitHub로 이식할 때

사용자가 시험 사이트를 확인하고 요청한 뒤에만 진행한다.
교수님 저장소의 최신 파일·권한·Pages 소스를 먼저 확인한다.
상대경로를 유지하고 기존 자료를 비교·보존한다. 계정별 인증정보는 복사하지 않는다.
이식 후 새 주소와 보고서 연결을 다시 검증하고 이 문서에 실제 배포 대상을 갱신한다.
