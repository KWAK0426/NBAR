# 홈페이지 인수인계

작성일: 2026-10-19 (한국시간)

## 1. 홈페이지의 목적

현장관측을 언제 어디서 수행했는지, 확보한 자료가 어떻게 처리되고 얼마나 진행됐는지, 그 결과를 어떤 보고서에서 볼 수 있는지 공유하는 공간입니다. 연구실 내부뿐 아니라 농과원 등 외부 기관도 이해할 수 있어야 합니다.

전체 연구 허브의 1차년도 과업은 다음 네 가지입니다.

1. 현장관측
2. 위성 기반 반사이방성 데이터셋 구축
3. BRDF 보정 알고리즘 프로토타입
4. LEOP 기반 BRDF 보정 알고리즘 테스트 및 적용

## 5. 확정된 화면 방향

### 최상위 허브

처음에는 2×2 사분면이었지만 사용자가 세로 1~4행을 요청했습니다. 이후 행 안의 3칸 구분선과 화면을 가득 채우는 배치가 답답하다고 하여 간결하게 수정했습니다.

현재는 번호, 제목·상태·짧은 설명, 페이지 버튼으로 구성합니다. 본문 최대 폭은 1180px이고, 4행 사이 간격은 16px입니다. 과업별 사진을 쓰지 않으며 헤더의 부산대 로고만 유지합니다. 이 수치는 향후 요청에 따라 조정할 수 있지만, 여백과 간결함이라는 방향은 유지해야 합니다.

### 현장관측 대시보드

- 피복 유형 탭: 농지 / 밭 / 나지 / 경사지.
- 날짜별 관측을 선택하면 관측 상세와 처리/산출 현황을 갱신합니다.
- 선택 관측 상세: 관측 시기·날짜, 사이클·전체 시간, 타프 설치·구성, 영상 수.
- 오른쪽에는 대표 RGB 모자이크 또는 미등록 상태를 표시합니다.
- 업무는 자료 정리 / 영상 처리 / 품질 검토 / BRDF 분석 / 보고서 작성의 5단계입니다.
- 상태 버튼을 누르면 해당 업무의 세부가 표시되고, 다른 관측 선택 시 자료 정리로 초기화됩니다.
- 자료 정리는 완료/미완료 중심, 영상 처리와 품질 검토는 패널/ELC 및 회차별 상태입니다.
- 타프 없는 날의 ELC는 `대상 아님`으로 표시합니다.
- 보고서 버튼의 준비 표시는 `HTML`과 `준비 중` 두 줄입니다.
- 보고서는 새 탭 또는 새 창으로 열립니다.

기존에 화면에 맞추고 목록만 스크롤하도록 요청한 이력이 있습니다. 이 동작은 페이지별 실제 뷰포트에서 다시 확인해야 하며, 무조건 내용이 잘리도록 overflow를 막아서는 안 됩니다.

## 6. 방법서와 회차 결과의 역할

반복 설명을 각 회차 보고서에 계속 넣지 않도록 공통 방법과 실제 결과를 나누었습니다.

### 전처리 방법서의 상위 단계

| 단계 | 내용 | 경계 |
|---|---|---|
| 0 | 데이터 취득 | 원영상·기준물·Ed·현장기록 확보 |
| 1-1 | 패널 기반 반사도 생성 | 원영상·패널 정보를 Metashape에서 보정 |
| 1-2 | 타프 ELC 기반 반사도 생성 | 방사보정, 상호교정, Ed, ROI, ELC 계수·검증·적용 |
| 2 | Metashape 처리 및 산출 | DEM, 추정 카메라 위치, Ortho Photos, Ortho Mosaic |

결과 방법서는 반사도 모자이크·품질검증, BRDF 분석, NBAR 생성의 세 상위 단계입니다.

사용자는 단계별 설명과 실제 수식을 원합니다. 한 줄짜리 요약, 많은 네모와 화살표만으로 본문을 대신하는 구성을 선호하지 않습니다. 수식은 LaTeX/MathJax로 렌더링합니다.

0단계 출처·산출물·확장자에 대한 더 자세한 대화는 있었지만 그 전체 내용이 HTML에 추가되지는 않았습니다. CSV·JSON·GeoTIFF 명세, 원자료 보존과 파일 출처 설명은 앞으로 확장할 수 있는 내용입니다. 실제 센서별 입력파일과 보정계수가 패키지 안에 모두 있는 것은 아닙니다.

## 7. 현재 동작과 구현상 한계

### 데이터 저장과 업데이트

서버나 관리 화면은 없습니다. 값을 바꾸려면 `site/data/nbar-data.js`를 편집하고 해당 파일을 다시 배포합니다. `NBAR_LAST_UPDATED`는 자동 시간이 아닌 수동 문자열입니다. GitHub push, Commit API, 자동 데이터 수집과 연결되어 있지 않습니다.

### 상위 상태와 세부 상태가 별도

`item.status`, `item.processing`, `NBAR_MOSAIC_CYCLE_PROGRESS`, `NBAR_QUALITY_CYCLE_PROGRESS`는 각각 따로 관리합니다. 현재 모든 완료 회차 기본값은 0인 반면 상위 영상 처리 상태는 진행 중입니다. 이는 실제 기록 모델의 한계이며 이번 패키징에서 자동 보정하지 않았습니다.

### 완료 회차는 순서형 개수

예를 들어 완료 수 2는 1회·2회 완료를 뜻합니다. 2회와 5회만 완료한 경우를 표현할 수 없습니다. 회차별 임의 상태 배열로 바꾸는 것은 향후 필요에 따른 모델 변경입니다.

### BRDF·보고서 세부의 50%는 임시값

`stagedTasks()`는 상위 상태가 진행 중이면 첫 항목만 진행 중 50%, 나머지를 예정 0%로 만듭니다. 사용자가 세부 완료를 입력한 결과가 아니므로 정확한 진행률로 소개하면 안 됩니다.

### ELC 적용 여부

`hasReflectanceTarp()`가 `schedule` 안의 `반사도 타프` 값이 `미설치`인지 검사합니다. 명시적 boolean 필드는 없습니다. 타프 세부 표시 문자열만 바꾸면 적용 여부와 표시가 달라질 수 있습니다.

대시보드는 타프가 있는 날에도 패널/ELC 두 줄을 표시합니다. 전처리 설명은 두 처리 경로로 나뉘어 있습니다. 두 결과를 항상 함께 만들 것인지, 관측마다 하나를 선택할 것인지는 운영 규칙으로 최종 확인할 사항입니다.

### 보고서 공개 조건

`reportButton()`은 보고서 작성 상태가 `예정`이면 준비 중을 표시합니다. 파일 존재 여부를 확인하지 않으며, 예정이 아니면 링크를 엽니다. 새 보고서를 공개할 때 실제 파일과 경로를 먼저 확인해야 합니다.

### 중복 필드

관측일·사이클·영상 수·시간이 상위 필드와 `schedule`에 중복되어 있습니다. 화면은 상위 값을 우선하는 경우가 있습니다. 수정 시 양쪽을 맞춰야 합니다. 필드 일원화는 별도 리팩터링 범위입니다.

### 영상 수 표기

선택 관측 상세의 `분광밴드별 장수 (10개 밴드)`는 하드코딩입니다. `imageCount`의 실물 집계 기준과 날짜별 센서·밴드 수를 자동 판별하지 않습니다. 숫자를 임의로 10배 또는 1/10로 환산하지 말고, 센서와 원자료 목록으로 기준을 확정한 뒤 수정합니다.

### 데이터의 HTML 삽입

대시보드는 데이터를 `innerHTML`로 템플릿에 넣습니다. 현재는 유지관리자가 직접 작성하는 로컬 JS 데이터입니다. 외부기관이 자유롭게 입력하는 폼이나 외부 JSON/API를 붙인다면 escape/검증을 함께 설계해야 합니다.

- 패널 처리 PPT: 사용자가 연결하길 원했지만 이 묶음에는 실제 PPT가 없음.
- 원자료 출처와 산출물 확장자 명세: 대화에서 상세화했지만 현재 HTML에는 완전한 명세표가 없음.
- 2~4번 과업: 준비 페이지의 틀만 존재. 데이터 수집·알고리즘 실행·성과목록은 연결되어 있지 않음.
- 헤더 시각적 통일: 요청한 방향이지만 페이지마다 CSS가 달라 미세 차이가 남아 있음.
- 별도 작업에서 생성한 최신 마스터 대시보드의 실적: 이 사이트에 동기화하지 않음.

## 9. 자료와 기술내용의 출처

관측 일정·회차·시간·영상 수·타프 구성은 사용자 제공 내용을 데이터 파일에 반영한 상태입니다. 기관명과 관측 목적 등 다른 필드는 기존 화면의 값이며 이번 포장 과정에서 새로 사실 검증하지 않았습니다.

전처리 방법서는 대화에서 정리한 작업 순서를 담습니다. MicaSense 방사보정, 센서별 계수, ROI 처리, Ed 정규화, Metashape 설정이 모두 이 패키지 안의 실행 코드와 일대일로 검증되어 있다는 뜻은 아닙니다. 과학적 기술 내용을 바꿀 때는 사용자의 실제 처리 코드와 공식 문서를 기준으로 검토합니다.
